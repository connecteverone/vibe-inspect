### US-005: Fix terminal session list reconciliation and persistence
Status: in_progress
Depends on: US-004

Description:
As a user, I want terminal session lists to stay consistent across reconnects and not appear empty when sessions exist.

Acceptance Criteria:
- [ ] Desktop provides a stable list of running/recent terminal sessions; mobile reconciles with local storage
- [ ] Mobile differentiates 'no sessions' from 'cannot fetch sessions' with distinct UI states
- [ ] Example: after reconnect, sessions created earlier appear in both mobile and desktop lists
- [ ] Negative case: if the desktop agent restarted and sessions are gone, mobile marks them as closed with a clear reason
